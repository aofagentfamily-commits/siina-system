# SIINA SYSTEM

ศูนย์กลางการทำงานและจัดการข้อมูลส่วนตัว — เว็บแอปที่รวมโปรเจ็กต์ ปฏิทิน การแจ้งเตือน ข้อความ Telegram ที่สำคัญ และการตั้งค่า ไว้ในที่เดียว ใช้ได้ทั้งคอมพิวเตอร์และมือถือ

## สิ่งที่มีในระบบ

| หมวด | ความสามารถ |
|---|---|
| เข้าสู่ระบบ | อีเมลและรหัสผ่าน ตั้งรหัสผ่านครั้งแรกครั้งเดียว (scrypt) ล็อกชั่วคราวหลังกรอกผิด 5 ครั้ง ปุ่มเปลี่ยนอีเมลและออกจากระบบ |
| หน้าแรก | ข้อความต้อนรับ การ์ดสรุป 6 ใบ (คลิกไปหน้ารายละเอียดได้) งานสำคัญวันนี้ และทางลัด 4 ปุ่ม |
| ห้องแชท | รายชื่อกลุ่ม Telegram พร้อมจำนวนที่ยังไม่อ่าน, ข้อความแบบแชท, ตอบกลับข้อความเฉพาะรายการ, ส่งข้อความในนามบอท, ป้องกันการส่งซ้ำ, แจ้งเมื่อส่งไม่สำเร็จและส่งซ้ำได้ |
| โปรเจ็กต์ | การ์ดแบบ Grid, ค้นหา, กรองตามสถานะ / รายการโปรด / คลัง, เพิ่ม แก้ไข ลบ, ปุ่มเปิดโปรเจ็กต์และแก้ไขโค้ด (ปิดใช้งานเมื่อไม่มี URL) |
| ปฏิทิน | มุมมองรายเดือน / รายสัปดาห์ / รายวัน, แสดงเฉพาะสัญลักษณ์ในช่องวันที่, เลือกประเภทที่ต้องการดู, เพิ่ม แก้ไข ลบ ทำเครื่องหมายเสร็จ, รายการกำลังจะมาถึงพร้อมแท็บกรอง |
| การแจ้งเตือน | ตั้งเวลาได้ (ตรงเวลา, 10 นาที, 30 นาที, 1 ชั่วโมง, 1 วัน, กำหนดเอง), ตรวจและสร้างการแจ้งเตือนฝั่งเซิร์ฟเวอร์ทุก 30 วินาที, กระดิ่งพร้อมจำนวนที่ยังไม่อ่าน, อีเมลแจ้งเตือนเป็นช่องทางเสริม |
| สรุปสำคัญ | รวมข้อความ Telegram ที่แท็กคุณ ตรงคำสำคัญ หรือตอบกลับคุณ รวมถึงนัดหมายและงานใกล้ครบกำหนด / เลยกำหนด พร้อมปุ่มเปิดต้นทาง อ่านแล้ว ติดตามภายหลัง เสร็จสิ้น รายการที่ยังไม่เสร็จจะไม่หายไปเมื่อมีข้อมูลใหม่ |
| ตั้งค่า | โปรไฟล์ (ชื่อ เขตเวลา รูปโปรไฟล์ Telegram User ID), Telegram (บอท กลุ่ม ตัวกรอง), การแจ้งเตือน, การแสดงผล (Animation, ขนาดตัวอักษร, Sidebar), ข้อมูลระบบ (ส่งออก JSON, ประวัติการทำงาน) |

ไม่มีหมวดทีม / พนักงาน และไม่ใช้ข้อมูลจำลองในการใช้งานจริง

## ความต้องการของระบบ

- Node.js **22.13 ขึ้นไป** (ใช้ `node:sqlite` ที่มาพร้อม Node ไม่ต้องติดตั้งฐานข้อมูลแยก)
- ไม่มีค่าใช้จ่ายด้านซอฟต์แวร์ ไม่ต้องมี SMTP เพื่อเข้าสู่ระบบ (ใช้เฉพาะอีเมลแจ้งเตือนถ้าเปิดไว้)

## ติดตั้งและเริ่มใช้งาน

```bash
npm install
cp .env.example .env
```

แก้ไฟล์ `.env` อย่างน้อยค่าเหล่านี้

- `APP_SECRET` — สุ่มอย่างน้อย 32 ตัวอักษร เช่น `openssl rand -hex 32`
- `ALLOWED_EMAILS` — อีเมลที่อนุญาตให้เข้าระบบ (คั่นด้วยจุลภาค)
- ค่า `SMTP_*` — ใช้สำหรับอีเมลแจ้งเตือนเท่านั้น (ไม่จำเป็นต่อการเข้าสู่ระบบ)

จากนั้นรัน

```bash
npm start
```

เปิด http://127.0.0.1:3000 แล้วกรอกอีเมลที่อยู่ใน `ALLOWED_EMAILS`

ทดสอบระบบ (ไม่ส่งอีเมลจริง ไม่เรียก Telegram จริง)

```bash
npm test
```

## ตัวแปรสภาพแวดล้อม (Environment Variables)

| ตัวแปร | จำเป็น | ความหมาย |
|---|---|---|
| `APP_SECRET` | ✅ | ความลับของระบบ ใช้ตรวจ Webhook และ session และเข้ารหัส Bot Token (อย่าเปลี่ยนโดยไม่จำเป็น ถ้าเปลี่ยนต้องกรอก Bot Token ใหม่) |
| `ALLOWED_EMAILS` | ✅ | รายการอีเมลที่เข้าระบบได้ |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | | เซิร์ฟเวอร์อีเมลขาออก (`SMTP_SECURE=1` สำหรับพอร์ต 465) |
| `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | | บัญชีและชื่อผู้ส่ง |
| `PORT`, `HOST` | | ค่าเริ่มต้น `3000` และ `127.0.0.1` |
| `PUBLIC_URL` | | ที่อยู่ HTTPS สาธารณะ ใช้เมื่อเลือกโหมด Webhook ของ Telegram |
| `COOKIE_SECURE` | | ตั้งเป็น `1` เมื่อใช้ HTTPS (ค่าเริ่มต้นเป็นจริงเมื่อ `NODE_ENV=production`) |
| `DATA_DIR` | | โฟลเดอร์เก็บฐานข้อมูล SQLite ค่าเริ่มต้นคือ `./data` |

## การเข้าสู่ระบบ (อีเมลและรหัสผ่าน)

1. ตั้งค่า `ALLOWED_EMAILS` ใน `.env` เป็นอีเมลที่อนุญาต (ตอนนี้คือ `aesiinasns@aofagent67.com`)
2. เปิด http://127.0.0.1:3000 แล้วกรอกอีเมลนั้น
3. **ครั้งแรกเท่านั้น** ระบบจะให้ตั้งรหัสผ่าน (อย่างน้อย 10 ตัวอักษร) พร้อมกรอกยืนยันอีกครั้ง
4. ครั้งถัดไปกรอกอีเมลและรหัสผ่านตามปกติ ถ้ากรอกผิด 5 ครั้งติดกัน ระบบจะล็อกการเข้าสู่ระบบ 15 นาที

ไม่ต้องตั้งค่า SMTP เพื่อเข้าสู่ระบบ ค่า SMTP ใช้เฉพาะตอนเปิดการแจ้งเตือนทางอีเมล

## ขั้นตอนเชื่อมต่อ Telegram Bot

1. ใน Telegram ค้นหา **@BotFather** แล้วส่ง `/newbot` ตั้งชื่อบอท จะได้ **Bot Token** (เก็บเป็นความลับ)
2. เพิ่มบอทเข้ากลุ่มที่ต้องการติดตาม และตั้งให้บอทเป็น **แอดมิน** (แนะนำ เพื่อให้รับข้อความทั้งหมดในกลุ่ม)
3. หากต้องอ่านข้อความทั่วไปในกลุ่มที่บอทไม่ได้เป็นแอดมิน ให้ส่ง `/setprivacy` ให้ @BotFather แล้วเลือก **Disable**
4. หา **Chat ID** ของกลุ่ม (ตัวเลข มักขึ้นต้นด้วย `-100`) โดยส่งข้อความในกลุ่มหนึ่งครั้ง แล้วเปิดลิงก์ `https://api.telegram.org/bot<TOKEN>/getUpdates` บนเครื่องของคุณเท่านั้น (ห้ามแชร์ลิงก์นี้เพราะมี Token อยู่)
5. ในระบบ ไปที่ **ตั้งค่า > Telegram** กดเพิ่มบอทแล้วกรอก Token กดเพิ่มกลุ่มแล้วกรอก Chat ID กด **ทดสอบสิทธิ์** เพื่อตรวจว่าอ่านและส่งข้อความได้
6. เพิ่มตัวกรอง: ชื่อผู้ใช้ที่ต้องการติดตาม (แท็ก), คำสำคัญ เช่น ด่วน รบกวน ตรวจสอบ, และ Telegram User ID ของผู้ส่งที่ต้องการติดตาม
7. หากต้องการให้ระบบรู้จักข้อความที่ตอบกลับข้อความของคุณ ให้กรอก **Telegram User ID ของคุณ** ในหน้า ตั้งค่า > โปรไฟล์

โหมดการรับข้อความ

- **Polling (ค่าเริ่มต้น)** — เซิร์ฟเวอร์ดึงข้อความจาก Telegram ทุก 5 วินาที ใช้งานได้ทันทีแม้ไม่มีโดเมน HTTPS
- **Webhook** — ต้องตั้ง `PUBLIC_URL` เป็น HTTPS สาธารณะ ระบบจะลงทะเบียน Webhook ให้อัตโนมัติ และตรวจ secret token ทุกคำขอ

ข้อจำกัดของ Telegram Bot API (ตามข้อกำหนด)

- ดึงประวัติข้อความเก่าที่เกิดก่อนบอทเข้ากลุ่มไม่ได้ ระบบเก็บเฉพาะข้อความที่บอทได้รับหลังจากเชื่อมต่อ
- การตรวจการตอบกลับทำได้เท่าที่ข้อมูลใน update มีให้ (ข้อความต้นทางต้องเป็นข้อความที่บอทได้รับ)
- สถานะอ่านในระบบแยกจากสถานะอ่านในแอป Telegram

## การแจ้งเตือนและงานเบื้องหลัง

- เซิร์ฟเวอร์ตรวจการแจ้งเตือนทุก 30 วินาที จึงต้องให้โปรเซสทำงานอยู่ตลอด (ใช้ systemd, pm2 หรือ Docker ก็ได้) การเปิดหน้าเว็บค้างไว้ไม่จำเป็น
- การแจ้งเตือนแต่ละรายการจะถูกสร้างเพียงครั้งเดียวต่อเวลาที่กำหนด แม้เซิร์ฟเวอร์รีสตาร์ต
- อีเมลแจ้งเตือนเป็นช่องทางเสริม เปิดได้ในหน้า ตั้งค่า > การแจ้งเตือน และต้องตั้งค่า SMTP ไว้แล้ว

## Deploy

1. ตั้ง `NODE_ENV=production`, `COOKIE_SECURE=1`, `HOST=127.0.0.1` แล้วตั้ง reverse proxy (เช่น Caddy หรือ Nginx) ที่รับ HTTPS และส่งต่อไปยังพอร์ต 3000
2. ตั้ง `PUBLIC_URL` เป็นโดเมน HTTPS ของระบบ หากต้องการใช้โหมด Webhook
3. ตั้ง `DATA_DIR` ไปยังโฟลเดอร์ที่มีการสำรองข้อมูล
4. รันด้วย process manager เช่น systemd

ตัวอย่าง unit file สำหรับ systemd (ปรับ path ให้ตรงกับเครื่องของคุณ)

```ini
[Unit]
Description=SIINA SYSTEM
After=network-online.target

[Service]
WorkingDirectory=/opt/siina-system
ExecStart=/usr/bin/node --env-file-if-exists=.env server/index.js
Restart=always
User=siina

[Install]
WantedBy=multi-user.target
```

## การสำรองข้อมูล

- **ส่งออกข้อมูล** — หน้า ตั้งค่า > ข้อมูลระบบ > ส่งออกข้อมูล (JSON รวมโปรเจ็กต์ นัดหมาย การแจ้งเตือน ข้อความ Telegram และตัวกรอง แต่ไม่รวม Bot Token)
- **สำรองฐานข้อมูล** — คัดลอกไฟล์ `siina.db` ใน `DATA_DIR` โดยหยุดเซิร์ฟเวอร์ก่อน (หรือใช้ `sqlite3 siina.db ".backup backup.db"`) และเก็บ `APP_SECRET` ไว้คู่กันเสมอ

## ความปลอดภัย (สรุป)

- ทุกคำขอ API ที่ไม่ใช่การเข้าสู่ระบบต้องมี session และข้อมูลทุกตารางแยกตามบัญชี
- Session เป็น token สุ่มที่เก็บเป็น hash ในฐานข้อมูล ใช้คุกกี้ HttpOnly และ SameSite=Strict มีอายุ 7 วัน และออกจากระบบจะยกเลิก session ทันที
- Bot Token เข้ารหัสด้วย AES-256-GCM หน้าเว็บเห็นเฉพาะ 4 ตัวท้าย
- ตรวจข้อมูลทุกฟิลด์ฝั่งเซิร์ฟเวอร์ ใช้ prepared statement กัน SQL Injection และแสดงข้อความทุกส่วนผ่านการ escape กัน XSS
- มี Content-Security-Policy, X-Frame-Options และจำกัดขนาดคำขอ
- ระบบ rate limit อยู่ในหน่วยความจำ จึงเหมาะกับการรันหนึ่งโปรเซส

## ข้อจำกัดที่ยังไม่ได้ทำ

- **สรุปด้วย AI** ยังไม่ได้เปิดใช้งาน ปุ่มแสดงสถานะชัดเจนว่าไม่พร้อมใช้งาน
- **โลโก้แบรนด์** บนหน้าเข้าสู่ระบบเป็นกล่องข้อความตกแต่ง ไม่ใช่โลโก้ทางการ หากต้องการใช้โลโก้จริง ให้เพิ่มไฟล์ SVG ของแบรนด์ตามแนวทางของแบรนด์นั้นเอง
- **การเชื่อมต่อจริง** กับ SMTP และ Telegram ยังไม่ได้ทดสอบกับบริการจริงในรอบนี้ ทดสอบเฉพาะส่วนที่จำลองได้ (ดู `npm test`) ควรทดสอบกับบัญชีจริงก่อนใช้งาน
- ฐานข้อมูลเป็น SQLite ที่เหมาะกับผู้ใช้คนเดียวหรือทีมเล็ก หากต้องรองรับผู้ใช้จำนวนมากควรย้ายไป PostgreSQL
- การแจ้งเตือนผ่านอีเมลและ Telegram ส่งเฉพาะอีเมล (ยังไม่มีการส่งการแจ้งเตือนเข้า Telegram)
